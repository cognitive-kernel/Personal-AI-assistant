# راه‌اندازی محیط توسعه

نیازمندی اولیه سیستم: Python 3.11 یا جدیدتر. لانچر، Ollama و مدل انتخاب‌شده را هم بررسی می‌کند.

## اجرای خودکار

از ریشه مخزن اجرا کنید:

```bash
python run.py
```

لانچر پیش از اجرای برنامه:
1. محیط مجازی `.venv` را می‌سازد یا از محیط موجود استفاده می‌کند.
2. وابستگی‌های تعریف‌شده در `pyproject.toml` را بررسی می‌کند.
3. **حتی اگر بسته‌ای از قبل نصب باشد، نسخه سازگار آن و وابستگی‌های لازم را در `prerequisites/wheels` نگه می‌دارد.** اگر مخزن محلی کامل و سالم باشد، دانلود را تکرار نمی‌کند؛ در غیر این صورت ابتدا بسته‌های موجود را استفاده می‌کند و فقط موارد لازم را دریافت می‌کند.
4. بسته‌های موردنیاز را در صورت نیاز از مخزن محلی نصب می‌کند.
5. نصب‌کننده رسمی Ollama را در `prerequisites/installers` cache می‌کند. اگر Ollama نصب نباشد، لانچر در Windows نصب‌کننده را اجرا می‌کند و در Linux اسکریپت رسمی را اجرا می‌کند. در macOS آرشیو رسمی را ذخیره و باز می‌کند تا نصب تعاملی تکمیل شود.
6. دسترسی به سرویس Ollama و وجود مدل را بررسی می‌کند؛ مدل پیش‌فرض `qwen2.5:7b` است و در صورت نبودن با Ollama دریافت می‌شود.
7. سرور فقط پس از آماده‌شدن پیش‌نیازها اجرا می‌شود.

فهرست بسته‌ها و اثرانگشت مخزن در `prerequisites/manifest.json` نگهداری می‌شود. تغییر وابستگی‌ها، محیط پایتون یا پلتفرم باعث بازبینی cache خواهد شد. این پوشه محلی است و در Git ثبت نمی‌شود.

گزینه‌ها:
- `python run.py --check-only`: آماده‌سازی پیش‌نیازها بدون اجرای سرور.
- `python run.py --dev --check-only`: آماده‌سازی وابستگی‌های توسعه و آزمون بدون اجرای سرور.
- متغیر `OLLAMA_MODEL`: تغییر مدل موردنیاز.

## اجرای آزمون‌ها

```bash
python run.py --dev --check-only
.venv/bin/python -m pytest
```

در Windows از `.venv\\Scripts\\python.exe -m pytest` استفاده کنید.

اگر نصب‌کننده سیستم‌عامل به مجوز مدیریتی یا تأیید تعاملی نیاز داشته باشد، باید آن مرحله را کامل کنید. اگر دانلود ناموفق باشد، برنامه متوقف می‌شود تا محیط ناقص اجرا نشود.

پایگاه داده‌ها در اولین راه‌اندازی ساخته می‌شوند. مسیرهای پیش‌فرض `data/settings.db` و `data/learning.db` هستند.


## تنظیم و سنجش مدل روی سیستم 32 GB / i5-12400

- runtime رسمی پروژه Ollama است؛ API مدل به‌صورت محلی استفاده می‌شود.
- برای مقایسه اولیه، مدل‌های Qwen3 8B و 14B را با یک مجموعه سؤال ثابت بسنجید. مدل 30B-A3B را فقط اگر حافظه آزاد کافی و زمان پاسخ قابل قبول بود آزمایش کنید؛ سرعت‌های تبلیغاتی را معیار پذیرش قرار ندهید.
- Context پایه را 8192 نگه دارید. اگر حافظه آزاد و کیفیت نیازمند متن بلند بود، 16384 را جداگانه ارزیابی کنید.
- thread را با مقادیر 8، 10 و 12 آزمایش کنید؛ برای هر تنظیم زمان پاسخ، توکن بر ثانیه، مصرف RAM و کیفیت پاسخ ثبت شود. تغییر تنظیم باید بر اساس نتیجه آزمون باشد.
- Embedding مرحله بعد از بازیابی واژه‌ای است. مدل پیشنهادی برای آزمایش اولیه nomic-embed-text از طریق Ollama است؛ قبل از استفاده در برنامه، وجود مدل، ابعاد بردار، زمان embedding و کیفیت بازیابی روی پرسش‌های فارسی/انگلیسی سنجیده شود.
- Chroma یا Qdrant فعلاً وابستگی اجباری نیستند. انتخاب پایگاه برداری باید پس از آزمون SQLite FTS5 به‌علاوه embedding و بر اساس حجم داده، پیچیدگی عملیات و کیفیت بازیابی انجام شود.

### ارزیابی تکرارپذیر بازیابی

مجموعه پرسش‌های برچسب‌خورده فارسی/انگلیسی در `tests/fixtures/retrieval_eval.json` قرار دارد. پس از ایندکس‌کردن منابع مربوطه، گزارش Recall@5 و MRR را اجرا کنید:

```bash
python scripts/evaluate_retrieval.py --k 5
```

این گزارش کیفیت را تضمین نمی‌کند؛ نتیجه فقط روی پرسش‌ها و URLهای برچسب‌خورده همین مجموعه معتبر است. اگر منابع هنوز در پایگاه دانش محلی نیستند، امتیاز پایین یا صفر به معنی آماده نبودن داده ارزیابی است. بازیابی embedding با مدل محلی `nomic-embed-text` به‌صورت best-effort فعال است؛ اگر مدل در دسترس نباشد، جست‌وجوی FTS5 ادامه پیدا می‌کند.

## API پایگاه دانش در شاخه فعلی

- POST /api/knowledge/sources با بدنه JSON شامل url و اختیاری title: دریافت و ایندکس یک صفحه از دامنه‌های مجاز.
- POST /api/knowledge/search با query و اختیاری limit: جست‌وجوی واژه‌ای در قطعات ایندکس‌شده.
- GET /api/knowledge/sources: فهرست منابع و تعداد قطعات.

دامنه‌های مجاز فعلی محدودند و redirect به‌صورت خودکار دنبال نمی‌شود. شرایط استفاده و مجوز بازاستفاده هر منبع باید جداگانه بررسی شود؛ در دسترس بودن عمومی یک صفحه به معنی اجازه بازنشر کامل آن نیست. این API را به شبکه عمومی منتشر نکنید.
