## قابلیت‌های پیاده‌سازی‌شده

1. **بودجه و خوداصلاح:** رزرو durable و idempotent در سطح job، سقف روزانهٔ سراسری اتمیک بین jobها، سقف‌های تغییرناپذیر برای همان روز، سقف جداگانهٔ تولید و یک اصلاح، حفظ خروجی باکیفیت‌تر، و ثبت usage/timing واقعی‌ای که Ollama گزارش می‌کند.
2. **Oracle و سنجش:** catalog نسخه‌دار موقت، اعتبارسنجی provenance و SHA-256 snapshot، evaluator با confusion matrix و accuracy/precision/recall/false-acceptance/false-rejection کلی و per-Oracle، گزارش per-case و CLI.
3. **Retrieval و امنیت:** بازبینی منبع و تغییر hash، اعتبارسنجی دوبارهٔ DNS/redirect، pin کردن اتصال به IP اعتبارسنجی‌شده همراه حفظ TLS hostname/SNI، حذف استفاده از proxy محیطی برای درخواست peer، مرزهای prompt-injection و fail-closed برای موارد نامعتبر.
4. **پایداری و idempotency:** ledger پایدار کانال‌های web/peer/sandbox، رزرو بودجهٔ مشترک، fencing تلاش‌های قدیمی، checkpoint/retry و ذخیرهٔ تجربه‌های شکست به‌عنوان هشدار غیرقابل‌اعتماد؛ هیچ شکست یا پاسخ peer به‌تنهایی دانش را ارتقا نمی‌دهد.
5. **چرخهٔ یادگیری:** هشدارهای شکست مرتبط به‌شکل محدود و صریحاً غیرقابل‌اعتماد وارد prompt درس می‌شوند؛ اصلاح خودکار فقط یک تلاش محدود دارد و نتیجهٔ ضعیف‌تر جایگزین خروجی بهتر نمی‌شود.

## موارد باقی‌مانده‌ای که بدون داده یا محیط بیرونی قابل تکمیل/اثبات نیستند

1. **اعتبار علمی واقعی:** در مخزن dataset مستقل و واقعاً داوری‌شدهٔ انسانی وجود ندارد. fixture فعلی مصنوعی است و evaluator را می‌آزماید، نه صحت علمی مدل را. برای محاسبهٔ معتبر خطای Oracle باید snapshotهای مرجع و برچسب‌گذاری مستقل انسانی تهیه شوند.
2. **هزینهٔ مالی provider:** سقف درخواست و توکن خروجی enforce می‌شود و usage موجود از Ollama ذخیره می‌شود؛ این موارد معادل صورت‌حساب پولی نیستند. محاسبهٔ هزینهٔ مالی تنها پس از تعریف جدول قیمت معتبر برای provider/model و مسیرهای واقعی مصرف ممکن است.
3. **آزمون زندهٔ prompt injection و شبکه:** آزمون‌های deterministic امنیت transport و policy را پوشش می‌دهند، اما جای ارزیابی مدل واقعی، DNS rebinding و رفتار شبکه در محیط هدف را نمی‌گیرند.
4. **پذیرش هدف:** اجرای واقعی Ollama/Docker و آزمون نهایی محلی Windows طبق درخواست به بعد از تکمیل کدنویسی موکول است.
5. **دامنهٔ Oracle:** Oracleهای فعلی عمداً کوچک و provisional هستند؛ افزودن domainهای جدید بدون منبع مرجع قابل ممیزی و آزمون‌های مستقل، کیفیت علمی قابل‌دفاع ایجاد نمی‌کند.
