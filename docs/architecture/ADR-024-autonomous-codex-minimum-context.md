# ADR-024: حداقل Context سخت‌افزارمحور برای Autonomous Codex

- وضعیت: پذیرفته‌شده
- تاریخ: 2026-11-21
- دامنه: ماژول Autonomous Engineering، preflight مدل Ollama، API readiness و UI

## زمینه

قرارداد عملیاتی Codex در این پروژه حداقل Context برابر ۶۴٬۰۰۰ توکن است. بااین‌حال، انتخاب سخت‌افزارمحور Context صرفاً بیشترین مقدار مثبت قابل تخصیص را برمی‌گرداند. در نتیجه ممکن بود preflight یک Context بسیار کمتر از ۶۴k را به‌عنوان تخصیص امن بپذیرد و اجرای وظیفه را آغاز کند.

شاهد عملیاتی: اجرای GitHub Actions با شناسهٔ [44907149358](https://github.com/cognitive-kernel/Personal-AI-assistant/actions/runs/44907149358) در 2026-11-21 مدل `gpt-oss:20b-codex-ctx11656` را با Context برابر 11,656 توکن انتخاب کرد؛ دو تلاش Codex انجام شد و در پایان گزارش نهایی فاقد completion marker معتبر بود. این شاهد ثابت می‌کند حداقل Context قراردادی رعایت نشده بود؛ اما به‌تنهایی ثابت نمی‌کند که Context پایین تنها علت نبود marker بوده است.

## تصمیم

1. تابع عمومی `select_context_window` در `app/ollama_context.py` یک پارامتر `minimum_context_tokens` با مقدار پیش‌فرض 1 می‌پذیرد تا کاربردهای غیر-Codex همچنان بتوانند Contextهای کوچک‌تر را انتخاب کنند.
2. preflight اختصاصی Codex در `scripts/verify_ollama_context.ps1` مقدار حداقل 65,536 را به helper می‌دهد و قبل از ساخت/بارگذاری مدل مشتق‌شده، کمتر بودن ظرفیت امن را رد می‌کند.
3. API readiness ماژول مهندسی تنها وقتی `model_context_supported=true` می‌دهد که ظرفیت سخت‌افزارمحور حداقل 65,536 توکن باشد.
4. endpoint ذخیرهٔ تنظیمات، مدل کم‌ظرفیت را رد می‌کند و مقدار ظرفیت امن فعلی و حداقل موردنیاز را به کاربر اعلام می‌کند.
5. UI ماژول مهندسی حداقل موردنیاز و ناکافی بودن ظرفیت فعلی را نمایش می‌دهد؛ دکمهٔ dispatch نباید در این وضعیت قابل استفاده باشد.
6. شکست preflight باید fail-closed باشد: هیچ task جدیدی به Codex تحویل نشود و task/checkpoint موجود حذف یا بازنویسی نشود.

## پیامدها

- اگر میزبان فقط 11,656 توکن Context امن فراهم کند، ماژول به‌درستی Not Ready نمایش داده و از اجرای نامعتبر جلوگیری می‌کند.
- برای اجرای واقعی باید حافظهٔ آزاد کافی فراهم شود یا میزبان/مدلی انتخاب شود که حداقل 64k را با حاشیهٔ امن پشتیبانی کند.
- Context بیشتر به‌تنهایی کیفیت خروجی یا موفقیت task را تضمین نمی‌کند؛ قرارداد گزارش، تشخیص خطا، تست، checkpoint و recovery همچنان باید جداگانه اعتبارسنجی شوند.
- helper عمومی به‌صورت پیش‌فرض محدودیت Codex را به سایر کاربردهای Ollama تحمیل نمی‌کند.

## آزمون و شواهد لازم

- Unit: پذیرش و رد ظرفیت در مرز 65,536، اعتبارسنجی ورودی minimum و حفظ رفتار عمومی helper.
- Service/API: Context کمتر از 64k readiness را false کند و ذخیرهٔ تنظیمات بدون فراخوانی GitHub رد شود.
- UI: مقدار ظرفیت امن و حداقل موردنیاز نمایش داده شود و readiness/dispatch غیرفعال بماند.
- Windows: PowerShell preflight قبل از ایجاد مدل Codex، ظرفیت کمتر از 64k را رد کند.
- Target host: پس از اصلاح، باید preflight واقعی روی حساب Runner مقدار حداقل 65,536 را گزارش کند؛ CI شبیه‌سازی‌شده جایگزین این شاهد نیست.
