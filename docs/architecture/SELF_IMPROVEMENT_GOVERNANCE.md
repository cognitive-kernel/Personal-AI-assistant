# حاکمیت چرخهٔ خودبهبود کد

## هدف و وضعیت

این مرحله یک دفتر ثبت و دروازهٔ حاکمیتی برای پیشنهادهای تغییر کد ایجاد می‌کند. این ماژول به‌تنهایی خودبهبود کامل نیست: نه patch را اعمال می‌کند، نه آزمون پروژه را اجرا می‌کند و نه کد را مستقر می‌کند.

## چرخهٔ وضعیت

1. proposed: diff، دلیل تغییر، hash و commit پایه ذخیره می‌شوند.
2. validated: قالب diff و فهرست مسیرها بررسی می‌شوند و git apply --check بدون نوشتن فایل روی همان commit پایه موفق می‌شود.
3. approved_for_pr: کاربر پس از تأیید صریح اجازه می‌دهد پیشنهاد برای بررسی انسانی/PR ادامه پیدا کند. این وضعیت به معنی merge، اجرا یا استقرار نیست.
4. rejected: پیشنهاد رد می‌شود. رخدادها در جدول تاریخچه باقی می‌مانند.

## محدودیت‌های امنیتی

- API فقط از loopback پذیرفته می‌شود.
- فعال‌سازی به تنظیم صریح SELF_IMPROVEMENT_REPO_ROOT با مسیر مطلق یک checkout Git شامل app/ و tests/ نیاز دارد.
- فقط فایل‌های Python زیر app/ و tests/ و فایل‌های Markdown زیر docs/ مجازند؛ حداکثر ۲۰ فایل و ۲۵۶ KiB در هر diff.
- مسیرهای traversal، rename، delete، symlink، submodule، binary diff و تغییر mode فایل رد می‌شوند. مسیرهای دارای symlink نیز رد می‌شوند.
- اعتبارسنجی فقط سازگاری diff با HEAD را بررسی می‌کند. گزارش صریحاً tests_executed=false و isolated_execution=false را ثبت می‌کند.
- HEAD باید بین ثبت، اعتبارسنجی و تأیید ثابت بماند؛ تغییر آن اعتبارسنجی/تأیید را متوقف می‌کند.
- هیچ endpoint برای اعمال patch یا اجرای خودکار کد وجود ندارد. تغییر واقعی باید از مسیر بازبینی‌شدهٔ Git/PR انجام شود.

## مراحل لازم برای تکمیل چرخه

- ساخت worktree موقت و قابل حذف برای هر پیشنهاد.
- اجرای آزمون‌ها در کانتینر digest-pinned با شبکهٔ غیرفعال و وابستگی‌های از پیش آماده.
- ثبت گزارش آزمون، hash ورودی/خروجی و provenance.
- تأیید جداگانه برای ساخت PR و تأیید انسانی قبل از merge.
- بررسی rollback با commit revert و آزمون بازیابی.
- بازبینی مستقل امنیتی Issue #52.

تا زمانی که این دروازه‌ها اضافه نشده‌اند، این قابلیت نباید به‌عنوان «خودبهبود خودکار» معرفی شود.
