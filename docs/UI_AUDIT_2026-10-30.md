**Baseline:** `main` at `f403ae13a03a9ac5e526879d40380221c879cff8` (after PR #571).
**Scope:** static dashboard structure, navigation implementation, UI acceptance criteria, semantic/contrast tests, and browser E2E test inventory. This is a repository-level audit; it does not claim manual screen-reader or target-host acceptance.

## Gaps and limits retained as open

1. The acceptance ledger's navigation description was stale: it said `aria-current=location` and scroll/resize/hash updates. The current implementation and browser assertion use `aria-current=page`; this audit corrects the documentation rather than changing working page-navigation behavior.
2. Navigation presence and HTTP 200 checks do not prove complete interaction parity for every destination. The settings form now has a Chromium regression for valid defaults, manual model entry, persistence, and API-failure recovery. PRs #591 and #593 added real-Chromium coverage for Kaggle/OCI consent, manual refresh, revocation, provider failures, programming-task submission/polling/result display, and queue-failure recovery. The remaining browser-level gaps are full Sandbox runtime/cancellation and AI-learning course/topic/lesson review plus reload recovery. Knowledge-source add/list/search and API-failure recovery are covered by `test_browser_knowledge_source_ingest_list_search_and_error_recovery`. Global and selected-course pause/resume are covered by focused tests, but this does not establish complete course/topic/lesson workflow coverage. Absence of a browser test alone is not proof of a broken feature.
3. Automated Chromium checks do not satisfy manual keyboard-only and screen-reader review.
4. Token-level contrast checks do not satisfy rendered component/state contrast review.
5. CI browser coverage is not target-host usability or operational acceptance.

## Day 2 entry criteria

For each candidate workflow above, map the UI action to its API endpoint, existing backend tests, success/loading/empty/error states, consent or confirmation boundary, and data-persistence behavior. Add only the missing browser assertions. Fix only a reproduced defect with a regression test. Do not broaden scope by adding duplicate navigation tests.

## Prioritized Day 2 browser-audit candidates

Priority is based on safety and impact, not on an assumption that the implementation is defective:

1. **Sandbox execution:** consent grant/revoke, fail-closed status lookup, bounded execution, cancellation, and task result/error recovery.
2. **Cloud planning:** validated requirement submission, dry-run output, stale-evidence handling, and explicit proof that execution remains unauthorized.
3. **Kaggle/OCI quota:** explicit opt-in/revocation, manual-only refresh, credential-path handling, and failure-state recovery.
4. **Programming assistance:** submit-to-queue flow, status/result rendering, validation, and retryable/permanent failure presentation.
5. **Knowledge sources:** add/list/search interaction, rejected URL feedback, and empty/error result states.
6. **AI-learning dashboard:** extend real-browser coverage for course/topic/lesson review and reload recovery; global and selected-course pause/resume now have focused regressions.

The first two are highest priority because their UI controls cross execution/authorization boundaries. The next three affect external/local resource access or user-facing task workflows. Existing backend and static tests remain the source of truth for already-covered invariants; browser tests should focus on user-visible state transitions and fail-closed behavior.


## Day 2 follow-up — sandbox browser regression

The original Day 1 inventory contained 27 browser tests. PR [#574](https://github.com/cognitive-kernel/Personal-AI-assistant/pull/574) added a 28th independent browser test, `test_browser_sandbox_consent_fails_closed_and_runs_bounded_task`, covering:

- A failed consent-status request leaves execution disabled.
- A successful status lookup still does not enable execution before explicit user consent.
- Granting consent enables the bounded execution form.
- The submitted source, timeout, and output limit match the user's entered values.
- A completed task is rendered and revoking consent disables execution again.

The test intercepts sandbox and task APIs in Chromium. It does not launch Docker or execute arbitrary code. PR-head tests, browser E2E, and dependency audit all passed; PR #574 was merged as `968b10bc7d731f7a241fbc9174d2837d994ed514`. Post-merge CI for that SHA completed successfully: tests, browser E2E, dependency audit, and Windows storage regressions passed. This closes only the repository-level browser test gap for the sandbox consent/run happy path and fail-closed status lookup; cancellation, runtime failure, Docker isolation, and target-host acceptance remain separate evidence items.
