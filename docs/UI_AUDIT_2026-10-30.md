## 2026-11-19 follow-up — stale AI-learning course response race

A targeted asynchronous-state review found a reproducible UI race in the active /ai-learning dashboard:

- loadCourse() applied a course response after awaiting the API without checking whether the user had selected a different course in the meantime. A slower response for the previously selected course could therefore replace the newly selected course's topics.
- loadRuns() had the same stale-response risk: an older request could render run history belonging to a previous selection after the user switched courses.
- The visible selector could show course B while the topic cards showed course A. This mismatch could mislead subsequent user actions, so the fix is limited to discarding stale responses; it does not alter API behavior, stored records, course selection, or mutation semantics.
- The Chromium regressions test_ai_learning_ignores_stale_course_response_after_selection_changes and test_ai_learning_ignores_stale_run_history_after_selection_changes delay the old course's detail and run-history responses separately, switch to course B, and verify that neither late response can replace course B's visible state.
- The same review found two chat races: loadConversationMessages() could let a late response for conversation A replace conversation B's messages and reset the internal delete target to A while the selector still showed B; a late conversation-list refresh could also reset a newer user selection to the selection captured when refresh began. The guarded loader now applies only the latest request for the currently selected conversation, sets the intended delete target immediately, and rejects a mismatched response identity. A non-explicit list refresh preserves the latest selection made while it was in flight. The Chromium regressions test_chat_ignores_stale_conversation_messages_and_keeps_delete_target_in_sync and test_chat_refresh_preserves_a_newer_conversation_selection cover both cases.
- The task dashboard had the same race: overlapping list requests could let a late response for the previous status filter replace the newly filtered task cards and cursor. refreshTasks() now applies results and errors only for the latest request and unchanged filter. The Chromium regression test_browser_task_filter_ignores_a_late_response_from_the_previous_filter delays the unfiltered list, selects failed, and verifies the failed-filter result remains visible.
- The sandbox consent panel also had a fail-closed race: a consent read started before revocation could finish afterward and re-enable the execution button. The panel now invalidates pending consent reads before grant/revoke mutations and ignores stale success/error responses. The Chromium regression test_browser_sandbox_revocation_cannot_be_overridden_by_a_stale_consent_read delays delivery of a pre-revocation enabled response, revokes consent, and verifies execution stays disabled.
- Kaggle quota, OCI limits, and experience auto-capture consent had the same stale-read risk. Their refresh paths now ignore responses invalidated by grant/revoke/refresh mutations; quota refresh buttons remain disabled unless explicit consent is active, and failed status reads disable them. Editable CLI/config fields are not overwritten while focused. The Chromium regression test_browser_quota_and_experience_consent_revocation_ignores_stale_reads delays the original enabled responses for all three panels, revokes each consent, and verifies the late responses cannot restore the enabled UI state.
- The audit started from a main baseline of 46 browser tests. PR [#784](https://github.com/cognitive-kernel/Personal-AI-assistant/pull/784) merged seven asynchronous-state/consent regressions; PR [#786](https://github.com/cognitive-kernel/Personal-AI-assistant/pull/786) merged a stale lesson-list/course-switch regression as `a174c9e5b4b4841fc7b68fffec107992214f5610`. Current main has 54 independent browser test functions. Exact-head full tests, Windows storage regressions, Browser E2E, Dependency Audit, and CodeQL passed for both PRs.

This is repository-side browser evidence only. Manual keyboard/screen-reader review, rendered-state contrast review, and target-host usability remain open.
