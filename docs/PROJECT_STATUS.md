# وضعیت یکپارچهٔ پروژه و زیرسامانهٔ یادگیری

> تاریخ بازبینی: 2026-10-26  
> شاخهٔ بازبینی: `feature/factual-independent-oracle-audit` (تغییرات این شاخه هنوز نیازمند CI و پذیرش عملیاتی هستند).  
> این سند مرجع واحد وضعیت فعلی، قابلیت‌های انجام‌شده و کارهای باقی‌مانده است.
> قرارداد پایدار تعریف «تکمیل» و چرخهٔ دانش در [LEARNING_COMPLETION_POLICY.md](learning/LEARNING_COMPLETION_POLICY.md) است. آزمون‌های محلی/انسانی عمداً به مرحلهٔ بعد موکول شده‌اند و برنامهٔ جداگانه در [POST_IMPLEMENTATION_VALIDATION_PLAN.md](learning/POST_IMPLEMENTATION_VALIDATION_PLAN.md) قرار دارد. تیک فقط برای قابلیتی است که وجود آن در کد یا قرارداد فعلی مخزن شواهد دارد؛ تیک به‌تنهایی به معنی پذیرش عملیاتی روی دستگاه مقصد یا اثبات صحت علمی نیست. تست‌های محلی و تست‌های انسانی در فهرست کارهای باقی‌ماندهٔ این سند شمرده نشده‌اند.

## 1. خلاصهٔ وضعیت

پروژه قابل اجرا و در حال توسعه است، اما برای بهره‌برداری حساس یا مستقل هنوز تأیید نهایی نشده است. قابلیت‌های تحقیق منبع‌محور، حافظهٔ تجربه، یادگیری مسیرمحور، صف پایدار وظایف، sandbox و گردش‌کار خودبهبوددهی کنترل‌شده وجود دارند؛ با این حال ارزیابی مستقل کیفیت دانش، خودکارسازی کامل چرخهٔ یادگیری، و برخی دروازه‌های عملیاتی و امنیتی باز هستند.

**مبنای وضعیت:** کد و مستندات شاخهٔ `feature/factual-independent-oracle-audit` بررسی شده‌اند؛ این موارد تا ادغام PR جزو `main` محسوب نمی‌شوند.

- [x] اتصال سیاست rubric به API و worker factual: ارزیابی ساختاری باید به hash نسخهٔ فعلی ادعا و hash کد آزمون متصل باشد؛ ارزیابی مردود پیش از اجرای sandbox رد می‌شود. معیارها هنوز ورودیِ اظهارشده توسط بازبین هستند و این اتصال به‌تنهایی ارزیاب مستقل خودکار یا اثبات صحت معنایی نیست.
- [x] ثبت ممیزی منبع مرجع برای آزمون factual: URL با HTTPS، hash مرجع، hash دقیق کد آزمون و نسخهٔ دقیق ادعا به هم متصل می‌شوند؛ worker گزیدهٔ ثبت‌شده را از میزبان رسمیِ allowlist‌شده دوباره واکشی می‌کند و اگر گزیده در صفحهٔ زنده نباشد پیش از sandbox fail-closed می‌شود. انتقال HTTP به IP اعتبارسنجی‌شده pin می‌شود، redirect دوباره بررسی می‌شود و بررسی TLS hostname حفظ می‌شود. hash صفحهٔ کامل با snapshot قبلی مقایسه نمی‌شود؛ حضور نقل‌قول زنده نیز به‌تنهایی اثبات‌کنندهٔ صحت علمی یا استقلال واقعی داوری نیست.

- [x] migration 28 و APIهای بررسی نامزد حافظهٔ موقت: ثبت شواهد به hash دقیق محتوا متصل است؛ hash منبع از واکشی زندهٔ HTTPS بررسی می‌شود؛ تناقض‌ها ارتقا را مسدود می‌کنند؛ ارتقای حافظهٔ دائم فقط با دو میزبان منبع، دو مدل مستقل و نتیجهٔ آزمون ثبت‌شده مجاز است. مسیرهای داخلی ثبت رأی مدل/آزمون از API عمومی قابل جعل نیستند.
- [x] اتصال worker صف برای واکشی امن چند منبع زنده، داوری دو مدل Ollama با digestهای متفاوت از مدل‌های تولید، ثبت hash ورودی/خروجی، آزمون سازگاری چندمنبعی و تصمیم fail-closed؛ دو تأیید مستقل باعث آماده‌شدن نامزد برای ارتقای تراکنشی می‌شود و تناقض تکرارشده در دو مدل و دو میزبان آن را با حفظ سابقه رد می‌کند. اگر منابع/مدل‌ها در دسترس نباشند، نامزد موقت می‌ماند.

## 3. کارهای باقی‌مانده در زیرسامانهٔ یادگیری

### 3.1 اعتبارسنجی دانش و شواهد

- [x] پیاده‌سازی ارزیابی معنایی در worker با مدل مستقل Ollama، rubric نسخه‌دار، بررسی اتصال آزمون به ادعا و رد پیش‌فرض در صورت کمبود شواهد؛ مدل بازبین باید digest متفاوت از مدل‌های تولید داشته باشد. worker اکنون میزبان رسمی را allowlist می‌کند، صفحهٔ زنده را با انتقال IP-pin‌شده واکشی می‌کند و وجود هر گزیدهٔ مورد استناد را در محتوای فعلی صفحه بررسی می‌کند. hash کل صفحه با snapshot تاریخی مقایسه نمی‌شود؛ اجرای زندهٔ مدل مقصد و ارزیابی برچسب‌خورده همچنان باز است.
- [x] کنترل قطعی سازگاری نسخهٔ منبع با نسخهٔ ادعا برای نسخه‌های عددی؛ نسخهٔ نامشخص یا ناسازگار fail-closed می‌شود. تطبیق محیط اجرا نیز با نسخهٔ ثبت‌شده و نسخهٔ runtime آزمون کنترل می‌شود.
- [x] طبقه‌بندی محافظه‌کارانهٔ ۱۵ دامنهٔ فنی برای بازیابی دانش factual (از جمله SQL Server، Windows Server، RouterOS، ESXi، MySQL، SQLite، Python، Rust، JavaScript، Docker، Linux، Cisco، Android، iOS و MetaTrader) و allowlist میزبان‌های مستندات رسمی؛ ماتریس دامنه/نسخه و رد موضوع مبهم در تست‌ها پوشش داده شده است.
- [x] گسترش runner factual از Python به SQLite: تست‌های Python/SQLite در Docker اجرا می‌شوند، نسخهٔ Python و SQLite جداگانه از خروجی محدود harness استخراج می‌شود و ارتقای `L2_tested` فقط در صورت تطبیق دقیق نسخهٔ محیط با ادعا انجام می‌شود.
- [ ] گسترش runner اجرایی به SQL Server، MySQL، JavaScript/Node، Rust و سایر دامنه‌های طبقه‌بندی‌شده؛ این دامنه‌ها فعلاً بازیابی/منبع دارند اما runner اختصاصی ندارند.
- [x] اتصال بازبینی factual به worker صف با یک تلاش، سقف ۴۵ ثانیه برای استنتاج، context حداکثر ۴۰۹۶ و خروجی حداکثر ۵۰۰ توکن؛ اجرای آزمون نیز در sandbox محدود می‌ماند.
- [x] مجموعهٔ طلایی نسخه‌دار و runner تکرارپذیر برای accuracy، precision، recall، false-acceptance rate، coverage، abstention، Brier score و ECE اضافه شده است (`python scripts/evaluate_factual_review_golden.py`). اجرای مدل مقصد و کالیبراسیون برچسب‌خورده، اعتبارسنجی محیطی است و در این چک‌لیست پیاده‌سازی شمرده نمی‌شود؛ جزئیات در محدودیت‌های عملیاتی ثبت شده است.
- [x] مسیر ارتقای `L2_tested` برای Python و SQLite: صف پایدار، ممیزی منبع/آزمون، بازبینی مستقل، اجرای sandbox، تطبیق دقیق نسخهٔ runtime و ثبت آزمون/ارتقا در تراکنش واحد پیاده‌سازی شده است؛ تست‌های رگرسیون برای جلوگیری از ارتقا بدون آزمون قابل‌اعمال نیز موجودند.
- [ ] گسترش مسیر ارتقای `L2_tested` به سایر دامنه‌ها پس از افزودن runner اختصاصی و ماتریس تست نسخه‌دار؛ تا آن زمان این دامنه‌ها fail-closed می‌مانند و قابل ارتقا نیستند.
- [x] بررسی سازگاری مهاجرت پایگاه داده و پشتیبان/بازیابی با آزمون‌های نسخه‌بندی schema، حفظ رکوردها/شناسه‌ها، `integrity_check` و `foreign_key_check`، پشتیبان قبل از مهاجرت، بازیابی کنترل‌شده و رد schema ناشناخته بدون تغییر فایل اصلی؛ آزمون‌های Windows CI نیز مسیر migration/restore را با موفقیت اجرا کرده‌اند.

### 3.2 ارزیابی و کنترل مسیر یادگیری

- [x] اتصال نتیجهٔ آزمون به پیشرفت مسیر: نمرهٔ یادگیرنده در `latest_score` ذخیره می‌شود و نمرهٔ حداقل ۸۰٪ سرفصل را کامل می‌کند؛ نمرهٔ پایین‌تر وضعیت را در حال انجام نگه می‌دارد. نمرهٔ کیفیت تولید درس از این معیار جدا و در `learning_jobs.quality_json` نگهداری می‌شود. نمره بر پایهٔ تطبیق متنی است و به‌تنهایی تسلط معنایی را اثبات نمی‌کند.
- [x] قفل پیش‌نیازها در سطح ایجاد job و تکمیل ارزیابی: مسیر خطی قبلی حفظ شده و migration 29 امکان DAG سفارشیِ چرخه‌گریز را در هر مسیر فراهم می‌کند؛ همهٔ پیش‌نیازهای مستقیم و انتقالی باید کامل باشند. بررسی در تراکنش نوشتنی SQLite انجام می‌شود و شاخهٔ آماده می‌تواند مستقل از سرفصل مسدود شروع شود.
- [x] ارزیاب معنایی مستقل از مدل تولیدکننده با rubric نسخه‌دار و کنترل digest برای پاسخ آزمون؛ خروجی در نمره/تکمیل اثر نمی‌گذارد و فقط برای بازخورد، تشخیص شکاف و راهنمایی درس استفاده می‌شود.
- [x] runner مجموعهٔ طلایی و معیارهای کالیبراسیون (accuracy، precision، recall، false acceptance، coverage، abstention، Brier و ECE) در مخزن وجود دارد؛ اجرای مدل‌های مقصد، مجموعهٔ برچسب‌خوردهٔ انسانی و تعیین آستانهٔ پذیرش به‌عنوان آزمون مرحلهٔ بعد در سند جداگانه ثبت شده است.
- [x] سنجش عملی تکرارپذیر و انتقال موقت پیاده‌سازی شده است: نقشهٔ قابلیت، آزمون‌های sandbox با منبع زنده و hashهای متمایز را می‌شمارد؛ برای انتقال، دو مسئلهٔ متفاوت از یک دانش retained_after_review، با دو نام آزمون، دو hash آزمون و شواهد منبع معتبر لازم است. وضعیت `transfer_provisional` ادعای تسلط عمومی نیست.
- [x] آزمون انتقال موقت در کد و نقشهٔ قابلیت پیاده‌سازی شده است؛ اجرای مجموعهٔ مرجع انسانی و کالیبراسیون انتقال در برنامهٔ آزمون پس از پیاده‌سازی ثبت شده است.

## 18. بازبین‌های خارجی با رضایت صریح — 2026-10-26

- تنظیمات provider بیرونی در UI فقط مشخصات endpoint/model/revision/host allowlist و نام متغیر محیطی کلید را ذخیره می‌کند؛ خود کلید API در دیتابیس ذخیره نمی‌شود.

- پاسخ provider باید system_fingerprint داشته باشد تا بتوان خروجی را به مدل/نسخه نسبت داد؛ در غیر این صورت بازبینی inconclusive است. این fingerprint هنوز تضمین صحت علمی یا مالکیت واقعی مدل نیست.
- تست‌های خودکار برای اعتبارسنجی تنظیمات، جلوگیری از IP خصوصی و الزام fingerprint نوشته شده‌اند؛ اتصال provider واقعی/کلید واقعی در مرحلهٔ آزمون بعدی انجام می‌شود.
