# معماری اولیه

## اصول
- اجرای محلی و اولویت CPU؛ استفاده از GPU تا زمان بررسی پشتیبانی backend فعال نمی‌شود.
- تنظیمات و داده‌های یادگیری در دو پایگاه SQLite مستقل نگهداری می‌شوند.
- لایه مدل از طریق adapter جداگانه قابل تعویض است؛ نسخه اول از Ollama استفاده می‌کند.
- ورودی کاربر و خروجی مدل، منبع معتبر تأییدشده فرض نمی‌شوند.
- هر کار یادگیری وضعیت، منشأ و خطا دارد؛ خروجی مدل با دانش تأییدشده یکی نیست.

## اجزا
- app/config.py: پیش‌فرض‌ها و متغیرهای محیطی.
- app/hardware.py: تشخیص CPU/RAM و محاسبه محدودیت‌های محافظه‌کارانه.
- app/db.py: تنظیمات و ساختار پایگاه داده یادگیری در فایل‌های مجزا.
- app/ollama.py: ارتباط HTTP محلی با Ollama، فهرست مدل‌ها و گفتگو.
- app/learning.py: ایجاد و اجرای کار یادگیری، ثبت شواهد و وضعیت.
- جدول knowledge_items: فقط درس‌هایی که از فیلتر اولیه ارزش ذخیره‌سازی عبور می‌کنند؛ وضعیت اولیه هر مورد unverified است و خودکار دانش تأییدشده تلقی نمی‌شود.
- فیلتر کیفیت، گزارش‌های خطای واکشی، محتوای کوتاه، تکرار زیاد و ارزیابی ناقص را رد می‌کند. خروجی ردشده به‌عنوان دانش ذخیره نمی‌شود و متن خام منبع آن حذف می‌شود؛ وضعیت و دلیل رد باقی می‌ماند.
- app/main.py: API و رابط اولیه مرورگر.

## مرزهای نسخه اول
- لایه دریافت و بازیابی منبع‌محور در app/knowledge_base.py از HTTPS و allowlist، سقف اندازه/زمان، اعتبارسنجی redirect، قطعه‌بندی هم‌پوشان و SQLite FTS5 استفاده می‌کند. اگر مدل محلی `nomic-embed-text` در دسترس باشد، embedding قطعات و ادغام رتبه FTS5/برداری با RRF نیز فعال می‌شود؛ در غیر این صورت جست‌وجوی واژه‌ای ادامه می‌یابد. معیارهای Recall@k و MRR در `app/retrieval_evaluation.py` و `scripts/evaluate_retrieval.py` فراهم‌اند، اما خط مبنای معتبر فقط پس از ایندکس‌کردن مجموعه ارزیابی قابل گزارش است. این قابلیت موتور جست‌وجوی وب عمومی نیست.
- پرسش‌های ارزیابی تولید می‌شوند، اما قبولی در آن‌ها هنوز اثبات مستقل یادگیری نیست.
- فیلتر ارزش ذخیره‌سازی، دروازه ابتدایی مبتنی بر قواعد است؛ جای ارزیابی معنایی مستقل، تأیید منابع یا بازبینی انسانی را نمی‌گیرد.
- بازیابی فعلی واژه‌محور است؛ embedding، جست‌وجوی برداری، بازیابی ترکیبی، reranking، گراف دانش، صف پایدار چندپردازه، زمان‌بندی دوره‌ای و توقف/ادامه هنوز در مراحل بعدی‌اند.
- API فعلاً برای استفاده محلی است و احراز هویت کاربر ندارد؛ آن را روی شبکه عمومی منتشر نکنید.


## چرخه ارزیابی درس — مرحله نخست

- هر کار یادگیری که از فیلتر کیفیت عبور کند، پرسش‌ها و کلید پاسخ دارد.
- کلید پاسخ تا قبل از ارسال پاسخ توسط کاربر از پاسخ عمومی API پنهان می‌ماند.
- پاسخ‌های آزمون در جدول assessment_attempts در پایگاه یادگیری ذخیره می‌شوند و تاریخچه تلاش‌ها به کار یادگیری متصل است.
- نمره نسخه نخست با تطبیق متنی نرمال‌شده و دقیق محاسبه می‌شود؛ این معیار به مترادف‌ها یا پاسخ تشریحی هم‌معنا امتیاز نمی‌دهد و تأیید مستقل علمی یا درک معنایی را اثبات نمی‌کند.
- این مرحله پیشرفت قابل‌اندازه‌گیری ایجاد می‌کند، اما قفل‌کردن سرفصل‌های بعدی بر اساس نمره، مرور فاصله‌دار و ارزیابی معنایی هنوز در مراحل بعدی هستند.


## مسیر فنی مورد توافق برای سخت‌افزار هدف

هدف توسعه: Windows 11، Intel Core i5-12400 (6 هسته/12 رشته)، RAM برابر 32 GB و GPU مجتمع. معماری باید local-first و CPU-friendly باشد؛ مصرف حافظه و زمان اجرا اندازه‌گیری شوند، نه اینکه سرعت یا کیفیت مدل از روی تعداد پارامترها فرض شود.

- **مدل:** Ollama به‌عنوان runtime اولیه حفظ می‌شود. مدل پیش‌فرض فعلی بدون بنچمارک تغییر نمی‌کند. Qwen3 8B و 14B گزینه‌های خط مبنا هستند؛ 30B-A3B فقط در آزمون کنترل‌شده از نظر سرعت، حافظه و کیفیت مقایسه می‌شود.
- **تنظیمات اجرا:** context اولیه 8192؛ تعداد thread قابل تنظیم و با آزمون 8، 10 و 12 مقایسه شود. هیچ مقدار واحدی برای همه بارها بهترین فرض نمی‌شود.
- **بازیابی دانش:** SQLite FTS5 فعلی حفظ شود. مرحله بعد embedding محلی از طریق API امبدینگ Ollama و جست‌وجوی برداری افزایشی است؛ تا زمانی که معیارها بهبود را ثابت نکرده‌اند، افزودن پایگاه برداری جداگانه الزامی نیست.
- **تولید مبتنی بر شواهد:** قطعات بازیابی‌شده باید همراه عنوان و URL به مدل داده شوند؛ منبع‌یابی و راستی‌آزمایی مستقل دو عملیات جدا هستند.
- **آزمون عملی:** اجرای SQL فقط در محیط آزمایشی محدود و با داده ساختگی/قابل‌بازنشانی انجام شود؛ اتصال به سرور عملیاتی یا اجرای آزاد کد مجاز نیست.
- **آموزش وزن‌ها:** fine-tuning فقط پس از داشتن مجموعه ارزیابی ثابت، داده آموزشی مجاز و اثبات اینکه RAG و اصلاح prompt کافی نیستند بررسی می‌شود.

ترتیب تصمیم‌ها: **قابلیت مشاهده و خط مبنا → کیفیت/منشأ داده → بازیابی ترکیبی → پوشش شکاف‌های دانش → آزمون عملی ایمن → ارزیابی مدل و تنظیم منابع → بررسی احتمالی fine-tuning.**
