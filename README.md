# Personal AI Assistant

دستیار هوش مصنوعی شخصی با رویکرد **local-first**؛ هدف این مخزن ساخت تدریجی یک Agent قابل توسعه، قابل آزمون و سازگار با منابع سخت‌افزاری سیستم است.

## تعریف Local-first

**Local-first به معنی Offline-only نیست.** برنامه باید تا جای ممکن ابتدا از پردازش، داده، ابزار، سرویس و cache موجود روی همان دستگاه استفاده کند. فقط وقتی منبع محلی موجود یا کافی نیست، یا ماهیت قابلیت به سرویس بیرونی نیاز دارد، می‌تواند با رعایت تنظیمات و مجوزهای همان قابلیت به اینترنت یا سرویس خارجی متصل شود.

- هستهٔ برنامه، رابط محلی، تنظیمات، پایگاه داده، حافظه، صف وظایف و پردازش‌های مستقل باید محلی باقی بمانند.
- قابلیت‌هایی مانند پژوهش وب، یادگیری از رابط ChatGPT، دریافت مدل یا بستهٔ مفقود، و عملیات GitHub در مهندسی خودکار ممکن است ذاتاً به اینترنت یا حساب/سرویس بیرونی نیاز داشته باشند. این نیاز باید صریح و فقط در همان قابلیت اعمال شود.
- نبود اینترنت، حساب یا ابزار یک قابلیت نباید اجرای هسته یا قابلیت‌های محلی و مستقل دیگر را متوقف کند. همان قابلیت باید وضعیت «نیازمند اتصال/پیش‌نیاز» را روشن گزارش کند و پس از بازگشت دسترسی قابل ادامه باشد.
- در صورت وجود ابزار یا دادهٔ محلی معتبر، برنامه نباید صرفاً به‌دلیل در دسترس بودن اینترنت، بی‌دلیل نمونهٔ خارجی را ترجیح دهد یا دادهٔ محلی را ارسال کند.
- راه‌اندازی و اجرای هسته نباید به نسخهٔ خاص یک shell، نام کاربر/گروه، مسیر نصب ثابت یا ابزار توسعهٔ نصب‌نشده وابسته باشد. مجوز مدیریتی فقط برای عملیاتی درخواست شود که واقعاً به تغییر سطح سیستم نیاز دارد؛ اجرای عادی برنامه نباید به حساب Administrator محدود باشد.


## سازگاری سخت‌افزار

هیچ مدل CPU، GPU، مقدار RAM یا سازندهٔ سخت‌افزاری مشخصی پیش‌نیاز نصب برنامه نیست. برنامه منابع واقعی میزبان را هنگام اجرا تشخیص می‌دهد و بودجهٔ thread، حافظه و context را بر همان اساس محدود می‌کند. GPU به‌صورت پیش‌فرض اجباری نیست و اجرای مدل محلی به ظرفیت واقعی حافظه و توان سیستم وابسته است.

مشخصات میزبان مرجع در گزارش‌های پذیرش پروژه صرفاً برای اندازه‌گیری عملکرد و تکرار آزمون‌ها نگهداری می‌شود؛ این مشخصات حداقل سخت‌افزار لازم یا محدودیت اجرای برنامه نیست.

## وضعیت فعلی

این پروژه همچنان در حال توسعه است و هنوز برای بهره‌برداری حساس یا مستقل تأیید نشده است. برای وضعیت دقیق مراحل، شواهد CI و معیارهای پذیرش باقی‌مانده به [وضعیت یکپارچهٔ پروژه و یادگیری](docs/PROJECT_STATUS.md) مراجعه کنید.

قابلیت‌های فعلی شامل این موارد است:

- اتصال local-first به Ollama، تشخیص سخت‌افزار و محدودسازی منابع.
- صف پایدار وظایف با checkpoint، lease، توقف/ادامه/لغو و آزمون‌های بازیابی.
- پژوهش منبع‌محور، ثبت منشأ، بررسی تعارض منابع و ابزار تشخیصی ارزیابی پاسخ.
- حافظهٔ تجربهٔ نسخه‌دار با رضایت صریح، بازبینی منابع، تازگی شواهد و بازخورد بازیابی؛ رأی مدل به‌تنهایی تأیید علمی محسوب نمی‌شود.
- Sandbox مبتنی بر Docker با محدودیت شبکه و منابع؛ CI شامل آزمون واقعی Docker با image قفل‌شده به digest است.
- گردش‌کار خودبهبود کنترل‌شده: بررسی patch، آزمون ایزوله، تأیید صریح و Draft PR/rollback؛ ادغام و استقرار خودکار وجود ندارد.
- سلامت فقط‌خواندنی ذخیره‌سازی، پشتیبان کامل سه دیتابیس، بازیابی در staging و کنترل نگهداری با تأیید.
- آزمون Chromium واقعی برای جریان‌های اصلی داشبورد، سلامت ذخیره‌سازی، ایجاد تجربه، رضایت/لغو رضایت و بازیابی پشتیبان در staging.

**مرزهای ایمنی:** تمام درخواست‌های HTTP از peerهای غیر-loopback با 403 رد می‌شوند. provisioning ابری و اجرای راه‌دور عمداً غیرفعال‌اند. API احراز هویت راه‌دور ندارد و نباید این محدودیت دور زده شود.

**پذیرش باقی‌مانده:** ممیزی کامل checkout و اجرای baseline روی ماشین هدف، اجرای زندهٔ ارزیابی Ollama همراه با داوری انسانی، آزمون‌های کامل مرورگر و crash/multi-process، اندازه‌گیری عملکرد روی سخت‌افزار هدف و بازبینی امنیتی مستقل [Issue #52](https://github.com/cognitive-kernel/Personal-AI-assistant/issues/52). موفقیت CI به‌تنهایی کیفیت factual مدل یا آمادگی محصول را ثابت نمی‌کند. برای آماده‌سازی گزارش ماشین هدف از ابزار [Target-host baseline](docs/TARGET_HOST_BASELINE.md) استفاده کنید؛ این ابزار دیتابیس‌ها را فقط‌خواندنی بررسی می‌کند و اجرای تست‌ها نیازمند گزینهٔ صریح `--run-tests` است. برای ثبت داوری انسانیِ ارزیابی زنده نیز [راهنمای Human Adjudication](docs/HUMAN_ADJUDICATION.md) را دنبال کنید؛ ابزار worksheet به‌تنهایی نمرهٔ کیفیت تولید نمی‌کند.

## شروع سریع

برای اولین اجرا نیازی به نصب قبلی Python ندارید. لانچر متناسب با سیستم‌عامل را از ریشهٔ مخزن اجرا کنید:

**Windows (PowerShell):**
```powershell
.\bootstrap.ps1
```

**Windows (CMD / اجرای مستقیم):**
```bat
bootstrap.cmd
```

**Linux و macOS:**
```sh
chmod +x ./bootstrap.sh
./bootstrap.sh
```

Bootstrap سیستم‌عامل و معماری CPU را تشخیص می‌دهد، نسخهٔ pin‌شدهٔ `uv` را از انتشار رسمی دریافت و SHA-256 آن را بررسی می‌کند، سپس Python 3.11 و محیط مجازی را در پوشهٔ محلی پروژه آماده می‌کند. فایل‌های runtime در `.runtime/` و محیط مجازی در `.venv/` یا مسیر جایگزین محلی نگهداری می‌شوند؛ مسیرهای کاربر و نصب ثابت فرض نمی‌شوند. اگر محیط مجازی موجود نامعتبر باشد، بدون حذف یا بازنویسی آن از مسیر جایگزین استفاده می‌شود.

پس از آن `run.py` وابستگی‌های Python، سرویس Ollama و مدل انتخاب‌شده را بررسی می‌کند. بسته‌ها در `prerequisites/wheels` cache می‌شوند. نصب Ollama در Windows و Linux به‌صورت خودکار تلاش می‌شود؛ نصب macOS ممکن است به تکمیل تعاملی نیاز داشته باشد. دانلودهای اولیه به اینترنت و دسترسی نوشتن در پوشهٔ پروژه نیاز دارند. در صورت نیاز به مجوز مدیریتی سیستم‌عامل، تأیید آن باید توسط کاربر انجام شود. برای جزئیات و محدودیت‌ها به `docs/DEVELOPMENT.md` مراجعه کنید.

برای نصب وابستگی‌های توسعه نیز اجرا کنید:

```bash
python run.py --dev
```

برای بررسی پیش‌نیازها بدون بالا آوردن رابط وب:

```bash
python run.py --check-only
```

رابط: http://127.0.0.1:8000  
مستندات API: http://127.0.0.1:8000/docs

برای جزئیات توسعه و معماری به `docs/DEVELOPMENT.md` و `docs/ARCHITECTURE.md` مراجعه کنید. برای مرزهای معماری، سیاست ادغام و دروازه‌های پذیرش نهایی نیز [گزارش یکپارچه‌سازی](docs/INTEGRATION_REPORT.md) را ببینید. **مرجع واحد مستندات زیرسامانهٔ یادگیری** در `docs/LEARNING.md` قرار دارد. ماژول اختیاری جمع‌آوری و بازیابی دانش از هوش مصنوعی در `app/ai_learning/` پیاده‌سازی اولیه دارد؛ راهنما در `docs/AI_LEARNING_CAPTURE.md` و استاندارد مهندسی در `docs/AI_LEARNING_ENGINEERING.md` است. راهنمای شروع آزمون و فعال‌سازی منوی داشبورد در `docs/AI_LEARNING_TESTING.md` قرار دارد. ماژول جمع‌آوری و بازیابی یادگیری به‌صورت پیش‌فرض فعال است؛ بازیابی دانش در پاسخ‌های چت همچنان جداگانه و با `AI_LEARNING_RETRIEVAL_ENABLED=1` فعال می‌شود. برای خاموش‌کردن کل ماژول مقدار `AI_LEARNING_ENABLED=0` را تنظیم کنید. پیش از بهره‌برداری باید CI و آزمون دستگاه مقصد بررسی شوند.  وضعیت کلی پروژه و دروازه‌های عملیاتی در `docs/PROJECT_STATUS.md` ثبت می‌شود. کاتالوگ دوره‌ها از مسیرهای `/api/learning/curricula` و `/api/learning/curricula/{slug}` قابل دریافت است.

## پایگاه دادهٔ موجود و مهاجرت امن

برای ساختار قدیمیِ مشخص‌شده در گزارش ماشین هدف، کد فعلی یک مهاجرت محافظت‌شده دارد: فقط fingerprint دقیقاً بازبینی‌شده پذیرفته می‌شود، از فایل اصلی backup پیش از تغییر ساخته و بررسی می‌شود، داده‌های سازگار به دیتابیس موقت منتقل می‌شوند و جایگزینی فایل فقط پس از بررسی ردیف‌ها، integrity، کلیدهای خارجی و ساختار نهایی انجام می‌شود. تاریخچهٔ شناسه‌های افزایشی SQLite نیز حفظ می‌شود.

- فایل backup با نامی مانند `learning.db.pre-migration-<timestamp>.bak` کنار دیتابیس ساخته می‌شود.
- ساختار ناشناخته یا دادهٔ ناسازگار نباید به‌صورت خودکار پذیرفته شود؛ در این حالت برنامه باید fail-closed بماند.
- **دیتابیس را حذف یا از نو ایجاد نکنید و تاریخچهٔ migration را دستی ننویسید.**
- پس از دریافت نسخهٔ حاوی مهاجرت، برنامه را یک‌بار اجرا کنید؛ سپس سلامت API و backup را بررسی کنید. این کار باید ابتدا در محیط قابل‌بازیابی انجام شود.

برای بررسی فقط‌خواندنیِ ساختار ناشناخته در PowerShell:

```powershell
.\.venv\Scripts\python.exe .\scripts\inspect_sqlite_schema.py .\data\learning.db --kind learning --output C:\Temp\learning-schema-report.json
```

گزارش schema و metadata را می‌سنجد و محتوای ردیف‌های کاربر را چاپ نمی‌کند؛ به‌تنهایی migration یا تعمیر انجام نمی‌دهد. پذیرش نهایی همچنان به اجرای واقعی روی Windows هدف، بررسی backup و موفقیت `/api/health` نیاز دارد.

## عامل مهندسی خودکار محلی

صفحهٔ عملیاتی عامل در `/autonomous-engineering` قرار دارد. این قابلیت از Codex CLI با مدل محلی Ollama و یک GitHub self-hosted runner ویندوزی استفاده می‌کند؛ کلید پولی OpenAI API لازم نیست. داشبورد فهرست کامل مدل‌های نصب‌شده را از `/api/tags` می‌خواند و هیچ مدل پیش‌فرض یا نصب‌نشده‌ای را به‌جای انتخاب صریح کاربر قرار نمی‌دهد. مدل انتخاب‌شده فقط پس از تأیید نصب، حداقل سقف Context برابر ۶۴٬۰۰۰ توکن و قابلیت `tools` ذخیره می‌شود؛ Workflow نیز Context را با توجه به metadata مدل و ظرفیت امن RAM محاسبه می‌کند و اگر ظرفیت امن به ۶۴٬۰۰۰ توکن نرسد اجرا را متوقف می‌کند؛ مقدار تخصیص‌یافته باید دقیقاً با مقدار انتخاب‌شده در `/api/ps` برابر باشد. در نبود مدل ذخیره‌شده یا شواهد معتبر، اجرا متوقف می‌شود. راهنمای نصب، امنیت، زمان‌بندی و محدودیت‌ها در [راهنمای عامل مهندسی محلی](docs/operations/CODEX_AUTONOMOUS_ENGINEERING.md) است. اجرای شبانه‌روزی به روشن‌بودن رایانه، اینترنت، Ollama و سرویس Runner نیاز دارد و به معنی تولید پیوستهٔ کد نیست.

## ماژول مستقل یادگیری از هوش مصنوعی

وضعیت فعلی، کارهای تکمیل‌شده و محدودیت‌های باقیمانده در `docs/AI_LEARNING_STATUS.md` ثبت شده و استاندارد معماری در `docs/AI_LEARNING_ENGINEERING.md` است. کد در `app/ai_learning/` قرار دارد و با دو feature flag مستقل، به‌صورت پیش‌فرض خاموش است. برای فعال‌سازی آزمایشی، `AI_LEARNING_ENABLED=1` و در صورت نیاز `AI_LEARNING_RETRIEVAL_ENABLED=1` را تنظیم کنید. رابط مدیریت در `/ai-learning` قرار دارد و از Playwright/Chrome قابل مشاهده برای کار با رابط ChatGPT استفاده می‌کند؛ افزونهٔ Chrome در `app/ai_learning/browser_extension/` به‌عنوان fallback مستند باقی مانده است. صف درخواست‌های ذخیره‌شده پس از راه‌اندازی بازیابی می‌شود، اما فعلاً فقط برای یک نمونهٔ برنامه است و ادامهٔ دقیق generation سمت ChatGPT تضمین نمی‌شود. جست‌وجوی دانش منتشرشده امکان ثبت بازخورد مفید/غیرمفید دارد. محتوا پیش از انتشار باید بازبینی شود؛ CI موفق جایگزین آزمون عملی روی رایانهٔ هدف نیست.

## امنیت اولیه
- رابط وب و همهٔ endpointها در middleware به اتصال loopback محدود شده‌اند؛ اتصال‌های غیر-loopback با 403 رد می‌شوند، حتی اگر سرور به‌اشتباه روی یک رابط شبکه bind شده باشد.
- نسخه اولیه فقط endpoint محلی Ollama را قبول می‌کند.
- API احراز هویت راه‌دور ندارد؛ برای دسترسی از LAN یا اینترنت این کنترل را دور نزنید. دسترسی راه‌دور به طراحی احراز هویت و بازبینی امنیتی مستقل جداگانه نیاز دارد.
- داده‌های محلی و فایل‌های پایگاه داده نباید به مخزن commit شوند.
