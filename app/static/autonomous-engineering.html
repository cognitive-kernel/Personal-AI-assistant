ONE-TIME SETUP

پیش‌نیازها و راه‌اندازی محیط فعلی

  1. سرویس Ollama را نصب و اجرا کنید.

    دانلود و نصب خود Ollama هنوز به راه‌اندازی سیستم‌عامل میزبان نیاز دارد. پس از فعال‌شدن سرویس، مدل انتخابی را از بخش تنظیمات همین صفحه دریافت کنید؛ وضعیت و درصد دانلود در UI نمایش داده می‌شود.

  2. GitHub CLI را نصب و احراز هویت کنید.

    Node.js 22 و Python 3.11 در ابتدای هر Job به‌صورت خودکار در محیط همان Workflow دریافت می‌شوند؛ نصب system-wide آن‌ها لازم نیست. GitHub CLI باید برای حساب برنامه احراز هویت شده باشد:

    gh auth login --web
  3. Runner و فضای وضعیت مشترک را بررسی و راه‌اندازی کنید.

    در نصب موجود، اسکریپت سرویس Runner، حساب اجرایی و مسیر نصب واقعی را از ویندوز کشف می‌کند؛ نام کاربر یا مسیر ثابت لازم نیست. اگر Runner وجود نداشته باشد، نام حساب سرویس غیرمدیر به‌صورت یکتا ساخته می‌شود. سرویس Broker با هویت محدود سیستم نصب می‌شود و فقط Runner و Broker به فایل‌های محافظت‌شده دسترسی مستقیم دارند؛ حساب‌های برنامه از کانال محلی محدود استفاده می‌کنند. اجرای مجدد ثبت Runner را حذف یا تکرار نمی‌کند. فرمان زیر را در PowerShell مدیر اجرا کنید؛ در صورت وجود چند Runner، فقط در آن حالت مسیر موردنظر را با پارامتر اختیاری مشخص کنید.

    powershell -ExecutionPolicy Bypass -File .\\scripts\\provision_autonomous_runner.ps1 -Repository "cognitive-kernel/Personal-AI-assistant"
  4. آمادگی را از هر دو زمینه بررسی کنید.

    بررسی برنامه را از هر حساب Windows که برنامه را اجرا می‌کند و بررسی Runner را از حساب سرویس Runner اجرا کنید:

    powershell -ExecutionPolicy Bypass -File .\scripts\check_autonomous_agent.ps1powershell -ExecutionPolicy Bypass -File .\scripts\check_autonomous_runner.ps1

OPERATING MODEL

عامل چگونه کار می‌کند؟

  • GitHub هر ساعت زمان‌بندی را بررسی می‌کند. در حالت زمان‌بندی‌شده، فاصله‌های ۱، ۲، ۴، ۶، ۱۲ یا ۲۴ ساعت اعمال می‌شوند؛ در حالت پیوسته، پس از ادغام دستی و موفقیت بررسی‌های پس از ادغام، اجرای بعدی آغاز می‌شود و heartbeat ساعتی بازیابی را پوشش می‌دهد.
  • Codex با حالت OSS و مدل انتخاب‌شدهٔ Ollama روی رایانهٔ شما اجرا می‌شود؛ درخواست استنتاج به endpoint محلی ارسال می‌شود.
  • عامل یک کار مستقل را انتخاب می‌کند، تغییرات و آزمون‌های مرتبط را آماده می‌کند و patch را تحویل می‌دهد.
  • اعتبارسنجی روی Runner میزبانی‌شدهٔ GitHub و بدون دسترسی به مدل یا اطلاعات محرمانه انجام می‌شود.
  • کنترلر پس از موفقیت آزمون‌های محلی، سه گردش‌کار مستقل و بررسی تغییرنکردن head و base، PR را برای بازبینی مالک باز می‌گذارد و هرگز آن را خودکار ادغام نمی‌کند. پس از ادغام دستی، کنترلر SHA دقیق merge و آزمون‌های پس از ادغام را بررسی می‌کند. استقرار خودکار انجام نمی‌شود.

تفاوت ۲۴ ساعته: Runner می‌تواند شبانه‌روزی روشن و آمادهٔ دریافت کار باشد؛ اما مدل به‌طور پیوسته کد تولید نمی‌کند. Workflowها نوبتی و محدود اجرا می‌شوند و زمان‌بندی GitHub تضمین لحظه‌ای ندارد. خاموش‌شدن رایانه، قطع اینترنت یا توقف سرویس Runner اجرای کار را متوقف می‌کند.

SECURITY BOUNDARIES

مرزهای امنیتی و محدودیت‌ها

  • عامل فقط از شاخهٔ اصلی اجرا می‌شود؛ کد Pull Requestهای ناشناس روی Runner شخصی اجرا نمی‌شود.
  • Codex توکن GitHub را دریافت نمی‌کند. کنترلر مورداعتماد با مجوز محدود Workflow، branch و PR می‌سازد و پس از موفقیت آزمون‌ها و تطبیق SHA دقیق، PR را برای بازبینی مالک آماده می‌کند؛ کنترلر هرگز ادغام خودکار انجام نمی‌دهد.
  • قوانین حفاظت شاخه و بررسی‌های اجباری دور زده نمی‌شوند؛ ادغام فقط با اقدام دستی مالک و مطابق سیاست‌های مخزن انجام می‌شود.
  • هیچ استقرار یا تغییر دیتابیس واقعی انجام نمی‌شود. آزمون پذیرش نهایی روی رایانهٔ هدف انسانی است؛ تأیید انسانی بین وظایف لازم نیست.
  • مدل محلی ممکن است در کارهای پیچیده کندتر یا کم‌دقت‌تر باشد؛ موفقیت CI جایگزین آزمون پذیرش نهایی نیست.
