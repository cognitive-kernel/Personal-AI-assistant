ONE-TIME SETUP

راه‌اندازی روی ویندوز

  1. Ollama را نصب و مدل را دریافت کنید.

    در ترمینال اجرا کنید:

    ollama pull gpt-oss:20b
  2. Codex CLI را نصب کنید.

    Node.js لازم است:

    npm install -g @openai/codex
  3. GitHub CLI را نصب و وارد حساب شوید.

    دسترسی لازم برای اجرای Workflow روی همین مخزن را تأیید کنید:

    gh auth login
  4. Self-hosted Runner بسازید.

    در مخزن GitHub به Settings → Actions → Runners → New self-hosted runner بروید. نسخهٔ Windows x64 را انتخاب و طبق دستور خود GitHub نصب کنید. هنگام پیکربندی، برچسب اضافی ollama را اضافه کنید.

  5. Runner را با حساب سرویس مجزا اجرا کنید.

    یک حساب Windows اختصاصی و غیرمدیر برای سرویس Runner بسازید؛ این حساب باید به endpoint محلی Ollama دسترسی داشته باشد، اما نباید با GitHub CLI وارد حساب شود یا فایل‌ها و اعتبارنامه‌های شخصی داشته باشد. حسابی که برنامهٔ محلی را اجرا می‌کند جداگانه با gh auth login احراز هویت می‌شود. توکن ثبت Runner موقت است؛ آن را در کد، چت یا فایل تنظیمات پروژه ذخیره نکنید.

  6. آمادگی محیط را بررسی کنید.

    در پوشهٔ پروژه، PowerShell را باز کنید و اجرا کنید:

    powershell -ExecutionPolicy Bypass -File .\scripts\check_autonomous_agent.ps1

OPERATING MODEL

عامل چگونه کار می‌کند؟

  • طبق تعداد اجرای روزانهٔ انتخاب‌شده (از ۱ تا ۲۴ بار در روز)، GitHub زمان‌بندی ساعتی را بررسی می‌کند و اجراها را بر اساس ساعت UTC به Runner محلی می‌سپارد؛ اجرای دستی جداگانه است.
  • Codex با حالت OSS و مدل انتخاب‌شدهٔ Ollama روی رایانهٔ شما اجرا می‌شود؛ درخواست استنتاج به endpoint محلی ارسال می‌شود.
  • عامل یک کار مستقل را انتخاب می‌کند، تغییرات و آزمون‌های مرتبط را آماده می‌کند و patch را تحویل می‌دهد.
  • اعتبارسنجی روی Runner میزبانی‌شدهٔ GitHub و بدون دسترسی به مدل یا اطلاعات محرمانه انجام می‌شود.
  • فقط پس از موفقیت همهٔ بررسی‌های تعریف‌شده، یک Pull Request پیش‌نویس ساخته می‌شود؛ ادغام و استقرار خودکار انجام نمی‌شود.

تفاوت ۲۴ ساعته: Runner می‌تواند شبانه‌روزی روشن و آمادهٔ دریافت کار باشد؛ اما مدل به‌طور پیوسته کد تولید نمی‌کند. Workflowها نوبتی و محدود اجرا می‌شوند و زمان‌بندی GitHub تضمین لحظه‌ای ندارد. خاموش‌شدن رایانه، قطع اینترنت یا توقف سرویس Runner اجرای کار را متوقف می‌کند.

SECURITY BOUNDARIES

مرزهای امنیتی و محدودیت‌ها

  • عامل فقط از رویدادهای شاخهٔ اصلی اجرا می‌شود؛ Workflow روی Pull Requestهای ناشناس اجرا نمی‌شود.
  • Codex مجوز نوشتن مستقیم در GitHub ندارد. انتشار Pull Request در یک job جداگانه و با مجوز محدود انجام می‌شود.
  • patch قبل از انتشار روی Runner میزبانی‌شده و بدون secret اعتبارسنجی می‌شود.
  • تغییر تنظیمات امنیتی، secrets، دیتابیس واقعی، انتشار نسخه و ادغام در main خودکار نیست.
  • مدل محلی ممکن است در کدنویسی پیچیده کندتر یا کم‌دقت‌تر از مدل‌های ابری باشد؛ نتیجهٔ CI جایگزین بازبینی مستقل و آزمون روی رایانهٔ هدف نیست.
