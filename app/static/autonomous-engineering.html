ONE-TIME SETUP

راه‌اندازی روی ویندوز

  1. Ollama را نصب و مدل را دریافت کنید.

    در ترمینال اجرا کنید:

    ollama pull نام-مدل-انتخابی
  2. Node.js LTS و GitHub CLI را آماده کنید.

    Node.js باید system-wide در PATH ویندوز باشد. با حسابی که برنامهٔ محلی را اجرا می‌کند، نشست موجود Chrome را برای احراز هویت GitHub به‌کار بگیرید:

    gh auth login --web
  3. Runner را در صورت نیاز provision کنید.

    اسکریپت موجود، حساب Windows اختصاصی و غیرمدیر (حساب سرویس) و Runner ویندوز با برچسب ollama را ایجاد و ACL فضای پیشرفت را تنظیم می‌کند. به PowerShell مدیر و مجوز Administration: write در مخزن نیاز دارد. اگر Runner از قبل به‌درستی نصب شده، آن را دوباره provision نکنید.

    powershell -ExecutionPolicy Bypass -File .\scripts\provision_autonomous_runner.ps1 -Repository "cognitive-kernel/Personal-AI-assistant" -RunnerAccount "runner-svc" -AppAccount "app-user"
  4. آمادگی هر دو حساب را بررسی کنید.

    ابتدا از حساب برنامه و سپس از حساب سرویس Runner بررسی کنید:

    powershell -ExecutionPolicy Bypass -File .\scripts\check_autonomous_agent.ps1powershell -ExecutionPolicy Bypass -File .\scripts\check_autonomous_runner.ps1

OPERATING MODEL

عامل چگونه کار می‌کند؟

  • GitHub هر ساعت زمان‌بندی را بررسی می‌کند. در حالت زمان‌بندی‌شده، فاصله‌های ۱، ۲، ۴، ۶، ۱۲ یا ۲۴ ساعت اعمال می‌شوند؛ در حالت پیوسته، پس از هر ادغام موفق اجرای بعدی آغاز می‌شود و heartbeat ساعتی بازیابی را پوشش می‌دهد.
  • Codex با حالت OSS و مدل انتخاب‌شدهٔ Ollama روی رایانهٔ شما اجرا می‌شود؛ درخواست استنتاج به endpoint محلی ارسال می‌شود.
  • عامل یک کار مستقل را انتخاب می‌کند، تغییرات و آزمون‌های مرتبط را آماده می‌کند و patch را تحویل می‌دهد.
  • اعتبارسنجی روی Runner میزبانی‌شدهٔ GitHub و بدون دسترسی به مدل یا اطلاعات محرمانه انجام می‌شود.
  • کنترلر پس از موفقیت آزمون‌های محلی، سه گردش‌کار مستقل، و بررسی تغییرنکردن head و base، PR را در main ادغام می‌کند. استقرار خودکار انجام نمی‌شود.

تفاوت ۲۴ ساعته: Runner می‌تواند شبانه‌روزی روشن و آمادهٔ دریافت کار باشد؛ اما مدل به‌طور پیوسته کد تولید نمی‌کند. Workflowها نوبتی و محدود اجرا می‌شوند و زمان‌بندی GitHub تضمین لحظه‌ای ندارد. خاموش‌شدن رایانه، قطع اینترنت یا توقف سرویس Runner اجرای کار را متوقف می‌کند.

SECURITY BOUNDARIES

مرزهای امنیتی و محدودیت‌ها

  • عامل فقط از شاخهٔ اصلی اجرا می‌شود؛ کد Pull Requestهای ناشناس روی Runner شخصی اجرا نمی‌شود.
  • Codex توکن GitHub را دریافت نمی‌کند. کنترلر مورداعتماد با مجوز محدود Workflow، branch و PR می‌سازد و فقط پس از موفقیت آزمون‌ها و تطبیق SHA دقیق merge می‌کند.
  • قوانین حفاظت شاخه و بررسی‌های اجباری دور زده نمی‌شوند؛ اگر سیاست مخزن ادغام خودکار را ممنوع کند، کنترلر fail-closed می‌شود.
  • هیچ استقرار یا تغییر دیتابیس واقعی انجام نمی‌شود. آزمون پذیرش نهایی روی رایانهٔ هدف انسانی است؛ تأیید انسانی بین وظایف لازم نیست.
  • مدل محلی ممکن است در کارهای پیچیده کندتر یا کم‌دقت‌تر باشد؛ موفقیت CI جایگزین آزمون پذیرش نهایی نیست.
